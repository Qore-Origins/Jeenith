# 志极 Jeenith —— 深度 AI 化与双端视觉升级规划

**规划日期**：2026-09-26
**规划范围**：AI 使用流程、个人化记忆、桌面端与移动端界面、浅色与深色主题
**产品原则**：保留现有术数能力；AI 协助理解与解释，不替代确定性算法；本地优先，由用户决定哪些内容发送给模型。
**状态**：规划已确认，本地案例流程首项已验收；其余三项产品待办待逐项验收

## 一、产品方向

Jeenith 从术数工具集合，逐步发展为以「问题—方法—结果—持续复盘」为主线的个人决策辅助应用。AI 覆盖自然语言问题理解、方法建议、结果解读与个人化复盘，但每一步都让用户看见依据并保留选择权。

现有手动选择术数的入口继续保留。用户可以直接使用熟悉的方法，也可以先描述问题，由应用协助梳理后再进入相应术数流程。

### 设计边界

- AI 可以整理问题、提出澄清问题、推荐术数并解释推荐理由；用户确认后才进入正式起课或计算。
- 卦象、命盘、签文等计算结果由应用现有的确定性算法与随机数流程产生。模型不得补造、改写或声称计算出未实际生成的结果。
- AI 解读应区分「计算所得」与「模型解释」，展示采用的资料来源、流派或前提；资料不足时说明不确定性。
- 个人档案、历史记录、对话与复盘默认保存在本机。首期不要求注册账号，不做云端记忆与同步。
- 每次请求模型前，用户可以查看并选择本次要发送的问题、结果、历史或个人档案；未选中的本地内容不进入请求。发送前提供内容预览与明确确认。
- API 密钥、凭据不进入导出备份。模型供应商与密钥配置沿用现有接入路径，接入层保持可替换。

## 二、AI 能力分层

### 1. 问题理解与方法引导

以自然语言作为新的入口。AI 提取问题主题、时间范围与用户提供的背景；信息不足时先询问澄清，不把推测当成事实。随后给出适合的方法建议、理由、适用边界和所需输入，并允许用户修改选择或切回手动选术。

用户确认后，应用调用对应的术数模块完成计算。AI 仅负责整理和建议，不直接生成卦象、命盘或随机结果。

### 2. 有依据的深度解读

解读输入由「用户本次选择的背景」与「应用实际算出的结构化结果」组成。输出将计算事实、传统资料引用、模型推演分开呈现，并保留后续追问能力。资料库按术数、流派、来源及版本组织；回答尽可能指向具体资料片段，避免把模型常识包装成古籍原文。

首期优先做好结果解释、多个维度的分析、反向追问和表达可追溯性。AI 给出思考辅助，不替用户作出重大人生或财务决定。

### 3. 本地个人助理与案例记忆

将一次问题下的提问、方法选择、计算结果、AI 对话、用户笔记和后续复盘组织为一个本地案例。用户可以手动保存个人偏好或重要背景；系统不得静默建立不可见的长期画像。

每次对话通过上下文选择器单独授权，可选择只发当前问题、当前结果，或额外选择某条案例/档案内容。界面显示将发送的内容，可在确认前移除条目。撤回选择后，本地资料仍保留在设备中。

### 4. 分阶段落地

1. **接入基础**：梳理现有 AI 流程，统一请求上下文、响应来源、错误状态与模型 Provider 边界；不改变术数计算的权威来源。
2. **问题引导**：加入自然语言问题入口、澄清问题、术数建议、用户确认与进入现有计算流程。
3. **深度解读**：整理可引用的本地资料结构，给结果解读附上依据、适用前提与不确定性提示。
4. **个人复盘**：建设本地案例、可编辑档案和逐次授权的上下文选择；后续再依据使用反馈评估同步需求，不预设云端化。

## 三、视觉与交互方向

### 1. 一套产品语言、两种主题、两种端侧布局

浅色与深色是同一应用的两种主题，使用相同的信息架构、组件与功能，不再拆成两个视觉方案。主题切换只改变表面、文字、边框、强调色及状态色，不改变内容层级与操作方式。

移动端与桌面端根据使用场景采用不同布局：移动端强调单手操作和逐步引导；桌面端利用宽屏展示并行信息和持续可见的上下文。两端共享设计令牌和组件规则，但不把手机页面简单放大到桌面。

### 2. 视觉基调

以沉静、清晰、有东方气质的编辑式界面为方向，减少全局黑金、高亮光晕、星空背景和大面积装饰字体。让卦象、命盘、罗盘等真实术数图形承担品牌识别，装饰仅在必要位置出现。

建议以低饱和石色、纸色、墨色、玉色和温润铜色构建设计令牌。初始色彩方向如下，实际实施时需检查文字、图标、边界与状态提示的可读性：

| 角色 | 浅色主题 | 深色主题 |
|------|----------|----------|
| 页面底色 | 暖石白 `#F0EEE5` | 深墨绿灰 `#171C19` |
| 卡片表面 | 暖白 `#FAF9F4` | 深苔灰 `#1D241F` |
| 主文字 | 墨灰 `#282923` | 暖纸白 `#E8E5DA` |
| 次级强调 | 玉灰绿 `#5E7465` | 柔玉灰绿 `#9CAA8E` |
| 点缀色 | 温铜 `#96784F` | 柔铜 `#A88D64` |

标题与关键结果可以保留克制的衬线字形；正文、数据、表单和按钮优先使用清晰易读的无衬线字体。红色等状态色只用于确有含义的状态，不作为装饰。

### 3. 桌面端布局

- 使用持久侧边导航、中央工作区和可收起的右侧上下文栏，充分利用桌面宽度。
- 中央工作区承担提问、方法选择、起课过程、结果和 AI 对话；右侧上下文栏展示当前案例、结果摘要、来源依据及本次可授权发送的资料。
- 桌面端支持鼠标悬停、键盘焦点和明确的选中状态；窗口缩窄时右侧栏可折叠，不以固定手机比例限制窗口。
- 图表可在中央区域获得足够展示空间；解释文本和结构化结果可以并列查看。

### 4. 移动端布局

- 使用单列、分步式流程和现有底部主导航；把高频主操作放在拇指容易触达的位置。
- 问题输入、补充信息、方法确认、结果、AI 解读按纵向阅读顺序组织；通过底部抽屉选择方法或本次发送的个人资料。
- 主操作可固定在底部安全区，但不得遮挡结果正文、键盘输入或系统手势区域。
- 复杂命盘和图表采用适合窄屏的分区、缩放或横向查看方式，不将桌面多栏压缩成拥挤的小卡片。

### 5. 组件与响应规则

- 建立共享的颜色、间距、圆角、文字层级、边框、焦点与状态令牌；深浅主题保持语义一致。
- 用窗口约束和布局断点切换组合方式，而不是只缩放字号和卡片尺寸。
- 输入、AI 生成、网络等待、失败、重试、来源查看、隐私授权等状态均需有清楚反馈。
- 动效沿用应用现有全局动效设置，优先用于状态变化与操作反馈，不以持续发光或装饰动画承担层级表达。

## 四、待办事项

以下四项构成首轮产品待办。每项均需同时满足验收条件后才能标记完成。

### 1. [x] 建立以问题为中心的本地案例流程

把问题、方法、计算结果、AI 对话、个人笔记和后续复盘串成一个可保存、可继续的本地案例；增加从术数结果一键进入对应 AI 解读的入口，并让当前结果自动成为可预览、可撤回选择的上下文来源。

**验收条件**：用户能新建、查看、继续和删除本地案例；可从结果页进入解读；模型请求前明确展示并确认将发送的内容；取消授权不会影响本地案例；保留直接进入现有术数的路径。

### 2. [ ] 补齐术数依据透明度与算法正确性资料

为各术数结果建立可核验的来源、流派、规则前提和适用边界说明；整理覆盖关键历法、边界日期、输入组合与随机流程的参考样例。AI 解读引用资料时标明来源，算法计算结果与模型阐释分别展示。

**验收条件**：每种已接入 AI 解读的术数都能说明结果字段的来源与解释范围；关键算法样例可复核；缺少资料时明确标示，不生成虚构引用；模型无法覆盖或修改应用实际计算结果。

### 3. [ ] 实现本地数据完整备份与恢复

提供用户可控的本地导出和恢复能力，覆盖个人档案、历史记录、AI 对话与案例。备份需包含格式版本，并支持恢复前预览、合并或替换选择；API 密钥及其他凭据始终排除。

**验收条件**：用户可导出并恢复各类本地资料；恢复前可确认内容和处理方式；格式版本不兼容或文件损坏时给出明确结果且不静默覆盖原数据；导出文件不包含密钥、令牌或密码。

### 4. [ ] 增加有依据、可手动覆盖的术数推荐

根据问题类别、用户提供的时间范围和所需信息，给出一至数个适合的术数选项，解释推荐原因、所需输入、适用范围与局限，并允许用户改选或自行进入任一术数。

**验收条件**：建议展示可理解的理由和必要信息；信息不足时先澄清或同时列出假设，不悄悄替用户作选择；用户始终能手动选术；选择确认前不会生成卦象、命盘或随机结果。

## 五、首轮范围与验收原则

- 本规划覆盖 AI 体验、视觉系统与上方四项待办，不包含账号体系、云同步或服务端个人记忆。
- 先让 AI 的建议可理解、计算结果可追溯、资料发送可控制，再扩展自动化和个人化深度。
- 桌面端与移动端分别验收主要任务路径；浅色与深色主题均需覆盖主要页面和交互状态。
- 视觉升级不应降低术数图表的辨识度、文字可读性、输入效率或用户对 AI 数据发送范围的理解。
